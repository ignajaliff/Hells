# Git Rules — Web

Convenciones de Git para mantener un historial limpio y entendible. Idénticas al kit de sistemas, con los agregados propios de Next.js.

## Ramas

```
main          → producción (solo código estable y testeado)
dev           → desarrollo activo, rama base para features
feature/[nombre]  → nueva página, sección o conexión
fix/[nombre]      → corrección de bug
hotfix/[nombre]   → corrección urgente directo a main
```

Ejemplos:
```
feature/seccion-promos
feature/conexion-web-config
fix/whatsapp-horario
hotfix/og-image-rota
```

Regla: nunca trabajar directo en `main`. Siempre desde `dev` o una rama `feature/`.

## Commits

Formato obligatorio: **Conventional Commits**

```
tipo(scope): descripción breve en español
```

Tipos permitidos:
* `feat` — nueva página, sección o funcionalidad
* `fix` — corrección de bug
* `chore` — tareas de mantenimiento (deps, config)
* `refactor` — cambio de código sin cambiar comportamiento
* `style` — cambios de diseño, estilos, animaciones
* `docs` — documentación
* `db` — cambios en schema o policies de Supabase
* `seo` — metadata, sitemap, datos estructurados, performance

Ejemplos:
```
feat(home): agregar sección de promos conectada a supabase
style(hero): animación de entrada con stagger
seo: agregar json-ld de localbusiness y og image
db(web): crear tabla web_config con rls publica de lectura
fix(contacto): honeypot no descartaba envíos de bots
```

Reglas:
* Descripción en minúscula y en español
* Sin punto final
* Máximo 72 caracteres en la primera línea
* Si el commit necesita más contexto, agregar cuerpo separado por línea en blanco

## Cuándo hacer commit

* Al terminar una sección o página funcional
* Al corregir un bug
* Antes de hacer un cambio grande (como "checkpoint")
* Nunca commitear código roto o con errores de TypeScript

## .gitignore obligatorio

```
node_modules/
.next/
out/
.env
.env.local
.env.*.local
*.log
.DS_Store
.vercel
```

El archivo `.env.example` SÍ debe commitearse (sin valores reales).

## Flujo de trabajo con IA

Cuando la IA hace cambios:
1. Revisar el diff antes de commitear
2. Verificar que no se commitearon archivos sensibles (.env, keys)
3. Verificar que `npm run build` pasa antes de pushear a main — en webs, main ES producción
